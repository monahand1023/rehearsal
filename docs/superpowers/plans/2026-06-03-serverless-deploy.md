# Serverless Deploy Implementation Plan

> **Execution note:** This is infrastructure, not unit-testable code. Execute it **directly** (not subagent-driven): build artifacts and verify with `docker`/`sam`, then do the real `sam deploy` as a **confirm-first** step. The deploy creates billable, internet-facing AWS resources and needs Dan's OpenAI API key + a chosen access code.

**Goal:** Deploy the rehearsal app (JP/STAMP mode, gated) to AWS as a single container Lambda behind a Function URL, using OpenAI for processing — no database, no domain, scale-to-zero.

**Architecture:** The existing FastAPI app, wrapped with Mangum (ASGI→Lambda), in a container image (Lambda Python base + static ffmpeg + parselmouth + the cloud requirements). SAM provisions the Lambda, a public Function URL, reserved concurrency, a 60s timeout, env config (cloud providers on, secure cookie), and a Budget alarm. Secrets live in SSM (SecureString); the deploy sources them and passes them as NoEcho template params → Lambda env vars (the app reads env vars unchanged).

**Tech Stack:** AWS SAM (installed), Docker (running), AWS Lambda container images, Lambda Function URL, SSM, AWS Budgets. Region `us-west-2`.

- [ ] **Step 2: Create `Dockerfile`** (Lambda Python base; bring a static ffmpeg+ffprobe; install cloud deps; copy engine/web/questions; CMD = the Mangum handler):
```dockerfile
FROM public.ecr.aws/lambda/python:3.12

# Static ffmpeg + ffprobe (the app shells out to both). johnvansickle static build.
RUN dnf install -y tar xz && \
    curl -sL https://johnvansickle.com/ffmpeg/releases/ffmpeg-release-amd64-static.tar.xz -o /tmp/ff.tar.xz && \
    mkdir -p /tmp/ff && tar -xJf /tmp/ff.tar.xz -C /tmp/ff --strip-components=1 && \
    cp /tmp/ff/ffmpeg /tmp/ff/ffprobe /usr/local/bin/ && \
    chmod +x /usr/local/bin/ffmpeg /usr/local/bin/ffprobe && \
    rm -rf /tmp/ff /tmp/ff.tar.xz && dnf clean all

# Cloud-only Python deps (no faster-whisper, no ollama).
COPY requirements-cloud.txt ${LAMBDA_TASK_ROOT}/
RUN pip install --no-cache-dir -r ${LAMBDA_TASK_ROOT}/requirements-cloud.txt

# App code.
COPY engine/ ${LAMBDA_TASK_ROOT}/engine/
COPY web/ ${LAMBDA_TASK_ROOT}/web/
COPY questions/ ${LAMBDA_TASK_ROOT}/questions/

# Cloud providers on by default in the image (overridable by Lambda env).
ENV REHEARSAL_LLM_PROVIDER=openai \
    REHEARSAL_TRANSCRIBE_PROVIDER=openai \
    REHEARSAL_COOKIE_SECURE=true

CMD ["web.lambda_handler.handler"]
```

- [ ] **Step 2a: Note on `QUESTIONS_DIR`** — `web/app.py` computes `QUESTIONS_DIR = BASE.parent / "questions"` where `BASE = web/`. In the image, `web/` is at `${LAMBDA_TASK_ROOT}/web` and `questions/` at `${LAMBDA_TASK_ROOT}/questions`, so `BASE.parent/questions` resolves correctly. No code change needed — just verify in Task 3.

- [ ] **Step 3: Build the image** (local):
Run: `docker build -t rehearsal:local .`
Expected: builds successfully (ffmpeg fetched, deps installed). If the johnvansickle URL is unreachable, substitute another static ffmpeg source and note it.

## Task 5: Secrets + deploy (CONFIRM-FIRST — needs Dan's key + access code + go-ahead)

**Do NOT run this task without Dan's explicit go-ahead — it creates billable, public resources.**

**Files:** create `scripts/put_secrets.sh`.

- [ ] **Step 1: Create `scripts/put_secrets.sh`** (stores secrets as SSM SecureString; Dan supplies the OpenAI key + access code; the ElevenLabs key is copied from the podcast param; the session secret is generated):
```bash
#!/usr/bin/env bash
set -euo pipefail
REGION=us-west-2
: "${OPENAI_API_KEY:?set OPENAI_API_KEY before running}"
: "${ACCESS_CODE:?set ACCESS_CODE before running}"
SESSION_SECRET="$(python3 -c 'import secrets;print(secrets.token_urlsafe(32))')"
ELEVEN="$(aws ssm get-parameter --name /your-project/elevenlabs-api-key \
          --with-decryption --query Parameter.Value --output text --region "$REGION")"

put() { aws ssm put-parameter --name "$1" --value "$2" --type SecureString \
        --overwrite --region "$REGION" >/dev/null; echo "  set $1"; }
put /rehearsal/openai-api-key   "$OPENAI_API_KEY"
put /rehearsal/elevenlabs-api-key "$ELEVEN"
put /rehearsal/access-code      "$ACCESS_CODE"
put /rehearsal/session-secret   "$SESSION_SECRET"
echo "done. access code and a fresh session secret stored in SSM."
```

- [ ] **Step 2: Dan runs the secrets script** (provides the values; the `!`-prefix keeps them in his shell):
```
!OPENAI_API_KEY='sk-...' ACCESS_CODE='<a long random code>' bash scripts/put_secrets.sh
```

- [ ] **Step 3: Build + deploy** (sources the secrets from SSM, passes them as params):
```bash
sam build
OPENAI=$(aws ssm get-parameter --name /rehearsal/openai-api-key --with-decryption --query Parameter.Value --output text --region us-west-2)
ELEVEN=$(aws ssm get-parameter --name /rehearsal/elevenlabs-api-key --with-decryption --query Parameter.Value --output text --region us-west-2)
CODE=$(aws ssm get-parameter --name /rehearsal/access-code --with-decryption --query Parameter.Value --output text --region us-west-2)
SECRET=$(aws ssm get-parameter --name /rehearsal/session-secret --with-decryption --query Parameter.Value --output text --region us-west-2)
sam deploy --guided --stack-name rehearsal --region us-west-2 --resolve-image-repos \
  --capabilities CAPABILITY_IAM \
  --parameter-overrides OpenAIApiKey="$OPENAI" ElevenLabsApiKey="$ELEVEN" AccessCode="$CODE" SessionSecret="$SECRET"
```
(`--guided` once to create `samconfig.toml`; subsequent deploys are just `sam deploy --parameter-overrides ...`.)
